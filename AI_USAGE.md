# AI Usage

Tool: OpenAI Codex

Used for: boilerplate generation, infrastructure scaffolding, and documentation drafts.

## What was generated

Codex generated initial versions of ctx.py, metrics.py, cache.py, reconciler.py, logging_setup.py, Dockerfile, and docker-compose.yml. These were reviewed and accepted after verifying correctness.

query_engine.py and main.py were generated then modified. The two-pass query engine structure came from Codex; the filter logic in _execute and the middleware ordering in FastAPI were adjusted manually after testing.

deploy.sh rollback logic was generated by Codex and verified by tracing through edge cases (no previous container, sed in-place on Windows vs Linux).

Redis was suggested for caching and rejected. The scope does not need it and the dict-based cache interface is already abstracted so swapping later is straightforward.



## How I verified

- 10 tests pass locally: pytest app/tests/ -v
- Ran the service with uvicorn locally, hit /health and /query manually
- Verified reconciler output on actual CSV data: S001 on 2026-04-01 gives 24.5C from both sources after conversion, within tolerance
- Verified correlation ID echoes back in response header
- Verified /metrics returns Prometheus text format with expected metric names
